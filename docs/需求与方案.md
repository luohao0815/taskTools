# 提词器 App —— 需求与方案文档

> 创建日期：2026-10-20
> 项目代号：Teleprompter（口播滚动提示词工具）

---

## 一、需求背景

自媒体博主录制口播视频时，稿子太长记不住，需要照着读，但稿子又不能出现在镜头画面里。

**核心矛盾**：稿子在屏幕上滚动方便照读 ⟷ 屏幕同时开着相机录像，面板不能挡住摄像头预览。

**目标**：博主在打开相机录视频的同时，能有一个悬浮的提词面板照着读稿。

## 四、核心技术方案

### 4.1 关键难点

iOS **不允许普通 App 的悬浮窗叠加在系统相机之上**。唯一合法且可靠的系统级方案是
**画中画（Picture in Picture, PiP）**——iOS 14+ 的 PiP 窗口可以悬浮在其他 App
（包括系统相机）上层，且支持拖动位置、缩放大小。

### 4.2 实现原理

1. App 内将稿子用 Core Text 排版，按滚动速度计算偏移量，逐帧渲染成位图；
2. 位图转换为 `CVPixelBuffer`，喂给 `AVSampleBufferDisplayLayer`；
3. 通过 `AVPictureInPictureController`（sample buffer 数据源）把滚动画面送进系统画中画；
4. 用户流程：提词器 App 调好速度与样式 → 一键进入 PiP → 切到系统相机 → 录像，
   PiP 小窗中稿子匀速滚动，照着小窗读稿。

### 4.3 已知风险

- 画中画窗口有尺寸上限（约屏幕 1/4~1/6），需保证字号够大、短句分行；
- 极少数全屏场景会强制关闭 PiP；系统相机在多数 iOS 版本实测可用，但大版本更新后可能失效；
- 进入 PiP 后 App 界面不可见，速度和样式需在进入前调好（PiP 内用系统播放/暂停按钮控制）。

### 4.4 技术栈与架构

- Swift + SwiftUI，iOS 15+ 部署目标，纯系统框架、零第三方依赖
- MVVM：
  - `Models/`：稿子数据模型（SwiftData 持久化）
  - `ScribeEngine/`：文本排版 + 滚动状态机（速度 → 偏移量）
  - `PipRenderer/`：位图渲染 → CVPixelBuffer → SampleBufferDisplayLayer（核心模块）
  - `Views/`：稿子编辑、设置面板、预演、悬浮引导页

## 五、打包与安装方案

| 项目 | 结论 |
|---|---|
| 打包方式 | **方案 A：GitHub Actions**（macOS runner 云端编译产出 IPA，本地无需 Mac） |
| 开发者账号 | **无 Apple 开发者账号** → 免费 Apple ID 签名，**7 天有效期**，到期需重签 |

安装路径（Windows 侧载）：
1. GitHub Actions 产出**未签名 IPA**；
2. 用 **AltStore / Sideloadly**（Windows 版）+ 免费 Apple ID 签名安装到 iPhone；
3. 每 7 天重新签名一次（AltStore 可在 WiFi 下自动重签）。
