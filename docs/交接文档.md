## 一、一句话概括

为自媒体博主开发 iOS 提词器 App：录口播视频时用**系统画中画（PiP）悬浮窗**滚动显示稿子，配合手机自带相机使用。当前处于 **M1（MVP）刚交付、待用户实测安装** 的阶段。

## 二、来龙去脉（为什么是这个方案）

1. **需求**：博主录视频记不住长稿子，需要一个能滚动显示稿子的面板，但不能挡住相机取景。
2. **平台结论**：iOS，录像用手机自带相机（不自研录像），交付代码 + 可安装 IPA，附加功能（速度/字体/颜色/高亮/横竖屏/镜像/.txt 导入）全都要。
3. **关键技术决策**：iOS 不允许普通 App 悬浮窗叠加在系统相机之上 → 唯一合法方案是 **iOS 14+ 画中画（PiP）**，通过 `AVSampleBufferDisplayLayer` + `AVPictureInPictureController` 把实时渲染的滚动文字送进 PiP 小窗。实现原理与风险详见需求文档第四节。
4. **打包决策**：用户无 Mac、无付费 Apple 开发者账号 → 走 **GitHub Actions macOS runner 云构建**（方案 A），产出未签名 IPA，用户用 Sideloadly/AltStore + 免费 Apple ID 签名侧载，**7 天过期需重签**。
5. **Gitee 问题**：用户曾问能否用 Gitee 打包——不能，Gitee Go 无 macOS 环境。如需 Gitee 存代码，可后续加「Gitee → GitHub 自动同步」Action（未实现）。

## 五、用户侧待办（M1 验收）

1. 在 GitHub 仓库 Actions 页手动触发 **Build IPA**（首次需授权启用 Actions）；
2. 下载 Artifact 中的 `Teleprompter-unsigned.ipa`；
3. 用 Sideloadly（推荐，Windows 版）+ Apple ID（建议用 App 专用密码）安装；
4. iPhone「设置 → 通用 → VPN与设备管理」信任证书；
5. 打开「提词器」看到 Hello World 界面 → M1 完成。

**若 CI 首次构建失败**：最可能是手工 pbxproj 的兼容性问题，把 Actions 日志报错原文要过来排查；本机可用 Python 做 pbxproj 结构校验（参考交接前做法）。

## 六、下一步工作（M2：提词核心）

用户验收 M1 后开始，目标：App 内可编辑稿并全屏滚动预演。

1. **数据层**：稿子模型（标题 + 正文 + 创建时间），SwiftData/Core Data 持久化，支持多条稿的增删改查列表页；
2. **滚动引擎**（`ScribeEngine/`）：速度（像素/秒）→ 偏移量的状态机，播放/暂停，支持拖动定位后继续滚；
3. **预演界面**（`Views/`）：全屏滚动显示，可调字体大小、文字颜色、背景色+透明度、当前行高亮、镜像翻转、横竖屏；
4. 注意：排版用 TextKit/Core Text 而非 SwiftUI 滚动，为 M3 的位图渲染管线复用做准备；
5. 更新 README 与里程碑状态。

### 后续里程碑速览

- **M3（核心难点）**：`PipRenderer/`——Core Text 排版 → CGContext 位图 → CVPixelBuffer → AVSampleBufferDisplayLayer → AVPictureInPictureController；配置 `AVAudioSession`（.playback 类别）PiP 才能存活；进入 PiP 前调好速度样式，PiP 内靠系统播放/暂停控制；**必须在真机+系统相机实测**。
- **M4**：.txt 导入（UIDocumentPicker）、图标、设置页打磨、文档收尾。
